\subsection*{\textbf{Game Settings:}}
\textcolor{purple}{\textbf{Functional Requirements:}}

\requirement{SFR}
{The game shall have a configuration that changes the player starting health.}
{This a difficulty setting to test how far a user can last on average before failing and restarting a run. For example, a user with minimum gaming experience
will typicall have a better time with the game if the user can last a little longer. Dialing the health will also limit how far a player goes on their initial runs, thus
preventing them from seeing too much of the game early on. Having this configuration will help to see the balance between player overall experience versus
the pace at which the content of the game is consumed at.}
{The user can change the starting health from a minmum of 50 to 150.}
{\hyperlink{UC-001}{UC-001}, \hyperlink{UC-002}{UC-002}, \hyperlink{UC-003}{UC-003}}
{game-variant-health}

\requirement{SFR}
{The game shall have a configuration that changes the average amount of resources gained after an encounter.}
{This is a pacing mechanic for the game. The user should not be able to purchase all the the upgrades from the central hub with only a short few runs, otherwise
the initial difficulty of the game gets trivialized from the added upgrades, not from the player's own skill. Having this configuration will also help distinguish
how a long the average player feels about the overall pace of game; different users have varying tolerances between the feeling of progression and grinding over and
over again.}
{The user can change the average of resources dropped between 10 to 20 between enemy encounters.}
{\hyperlink{UC-001}{UC-001}, \hyperlink{UC-002}{UC-002}, \hyperlink{UC-003}{UC-003}}
{game-variant-droprate}

\requirement{SFR}
{The game shall have a configuration that changes the cost of each purchasable upgrade.}
{Changing the purchase cost is slightly different from \ref{game-variant-droprate}, because it changes how players percieves the purchase progression. 
A player will gauge how far he or she has to go before the being being able to purchase a new upgrade. If the cost is too high, than this discourages the player
from ever buying it. If the cost is too low then this runs the risk of completing all purchase too fast; there needs to be a balance for the cost.}
{The user can change the additional cost of each purchaseable upgrade from zero to 50.}
{\hyperlink{UC-004}{UC-004}, \hyperlink{US-004}{US-004}}
{game-variant-cost}

\subsection*{\textbf{Central Hub:}}
\textcolor{purple}{\textbf{Functional Requirements:}}

\requirement{SFR}{Permanent progression should be characterized by the player keeping some progression after they lose. 
This could be a certain resource/currency, or things the player discovered in each attempt.}
{The player should some feel some sense of improvement or accomplishment during the gameplayer, otherwise they would not feel the need to continue}
{The game keeps the same amount of resources after the player has failed the attempt}
{\hyperlink{UC-002}{UC-002}, \hyperlink{UC-004}{UC-004}}
{permanent-progression}

\requirement{SFR}{During gameplay, the player can gain resources sent from the central hub, changing the gameplay experience for each run. 
This progression does not persist after the player loses.}
{This is a vital feature the game uses to help improve the odds of the player going further during a game session}
{The game transfer magic points to the player each combat instance.}
{\hyperlink{UC-002}{UC-002}, \hyperlink{UC-004}{UC-004}}
{upkeep-during-gameplay}
