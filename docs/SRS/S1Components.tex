The project can be broken down into the following core components:

\begin{itemize}
	\item \textbf{Physical Controls}: This component handles input between the \hyperlink{player}{player} and the game. This can be achieved through a computer keyboard or a standard game controller. The input enabled by this component is typically constrained/enforced through the \hyperlink{UI}{UI}.

	\item \textbf{User Interface (\hyperlink{UI}{UI})}: This component allows the \hyperlink{player}{player} to interact with the game (using their preferred interaction method). This is shown through various menus, buttons and other visual prompts and ensures the game is intuitive to navigate. 

	\item \textbf{Game Settings}: This component contains  settings that allow the \hyperlink{player}{player} to change various settings. This allows the \hyperlink{player}{player} to customize how they interact with the game through various settings (gameplay, audio, visual, etc.). 

	\item \textbf{Combat System}: This component contains the main "gameplay loop" of the system, which is the main way the \hyperlink{player}{player} will interact with the game. This includes everything needed for a combat encounter, such as player and enemy properties, possible actions, current game state and the condition(s) needed to win a fight.

	\item \textbf{Map System}: This component contains the main means of traversal for the \hyperlink{player}{player}, bringing together the various encounters and giving a sense of progression and a goal to work towards. 

	\item \textbf{Central Hub}: This component contains the hub area for the game, which can be divided into two main functionalities:
	\begin{itemize}
		\item \textbf{Permanent Progression}: Permanent progression is characterized by the \hyperlink{player}{player} keeping some progression after they lose. This could be a certain resource/currency, or things that you discover in each attempt.

		\item \textbf{Upkeep During Gameplay}: During gameplay, you can gain resources sent from your central hub, changing the gameplay experience for each run. This progression does NOT persist after the \hyperlink{player}{player} loses.
	\end{itemize}
\end{itemize}

The \hyperlink{player}{player} uses Physical Controls mentioned above to interact with the game's many components listed above. Input is guided by the \hyperlink{UI}{UI}, which constrains the \hyperlink{player}{player} to certain intended methods of interaction.
