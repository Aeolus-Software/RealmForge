\requirement{SSR-001}
{Save data shall be associated with specific game profiles saved on the device.}
{Being able to have multiple game profiles improves usability of the system}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-002}
{The system shall ensure all play tester information and evaluation metrics are securely stored and restricted from unauthorized access.}
{Play testers should feel comfortable to test the game without fear of having their information exposed to third parties.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-003}
{Save files and player data shall be validated upon launch, detecting and rejecting malformed data.}
{Losing data or having files be corrupted during launch will result in player frustration.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-004}
{Unsaved progress or session data shall be stored locally on the user's device if an unexpected exception or failure occurs.}
{Losing progress in-game after unexpected exceptions occur will result in immense frustration in users.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-005}
{The application shall handle unexpected runtime exceptions gracefully to prevent permanent data corruption to local save files or destabilization of the host operating system.}
{Failure of the system resulting in destabilization outside of the game environment is potentially dangerous to host system.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-006}
{The application shall display a warning about flashing lights and not have excessive flashing lights during gameplay.}
{Excessive flashing lights without a warning previously displayed is dangerous for users with epilepsy.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-007}
{The system shall store backups of combat reward data and verify user receives these rewards.}
{Not gaining rewards when the user should will negatively impact user experience greatly.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-008}
{The system shall clearly distinguish between actions which are available and unavailable to the user during map navigation, combat, and central hub modification.}
{Player can become frustrated while trying to make relevant decisions if their options are not clearly laid out.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-009}
{The system shall avoid using certain colours to convey important information.}
{The system must be accommodating to users with colour blindness.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-010}
{The system shall provide guidance how to connect input devices.}
{Difficulty in connecting input devices can waste user's time and frustrate them during the process.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-011}
{The system shall detect when new input devices are connected.}
{Makes the process of connecting an input device quick and simple for the user.}
{Fit Criterion}
{Traceability tags}

\requirement{SSR-012}
{The system shall reconfirm it is in the proper game state after major game state transitions occur}
{The user getting locked out of progressing through game states will prevent playing the game}
{Fit Criterion}
{Traceability tags}
