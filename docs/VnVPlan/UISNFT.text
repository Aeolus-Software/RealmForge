The system tests listed below are planned to verify the implemented system as a 
whole against non-functional requirements related to its user interface 
component. 
These requirements can be found in the SRS \cite{SRS}, listed in 
section S.2's 
non-functional requirements (they are spread across multiple categories), as 
well as in section 
S.2's Safety and Security Requirements (some safety requirements presented in 
the document relate to non-functional qualities of the system). Tracebility 
relationships between all 
system tests and covered requirements are provided in the traceability table in 
section 4.3 of this document.

\begin{enumerate}

\item \nonfunctest{UISNFTmapappearance}
{Game World Location Appearance Variety}
{Dynamic, Manual}
{The RealmForge software has been launched on a compatible device, and 
initialized to a game state where the overall game world is displayed during a 
gameplay session.}
{The game world is traversed using inputs to the software as a player would 
during gameplay (assuming the software is 
initialized to a state where the player is permitted to move to each world 
location), using a valid input device (keyboard and mouse, or a controller).}
{The total game world displays at least 
\hyperlink{DISTINCT_LOCATION_ICONS}{DISTINCT\_\allowbreak LOCATION\_\allowbreak 
ICONS}
 unique 
icons/symbols for the locations players can traverse to (these can be repeated 
across the game world as needed). A used symbol is distinct from others if it 
is visibly differentiated by colour (following required accessibility 
guidelines), or the images displayed (a mountain vs.~a forest, for example).}
{The system tester will launch the RealmForge software, and initialize its 
state to the overall game world (where each game world location is valid for 
travel). The tester will then traverse the game world using a valid input 
device as a player would, and verify that at least 
\hyperlink{DISTINCT_LOCATION_ICONS}{DISTINCT\_\allowbreak LOCATION\_\allowbreak 
ICONS} distinct location symbols are displayed in the total game world, 
following the 
defintion of distinct described above.}

\item \nonfunctest{UISNFTstatetransitions}
{Game State Display Transitions}
{Dynamic, Manual}
{The RealmForge software has been launched on a compatible device, in its 
development environment.}
{The game is initialized to each generalized state it can enter (main menu, 
configuration menu, save data management menu, game world, and combat 
encounter) and each potential scene/menu transition for each state is executed 
via a valid 
input device (entering the configuration menu from the main menu, for example).}
{The system completes and displays each prompted game scene transition in under 
\hyperlink{TRANSITION_TIME}{TRANSITION\_\allowbreak TIME} seconds. During each 
transition, the system fades the display output to black (or another suitable 
intermediate screen), to communicate that the transition is ocurring.}
{The system tester will launch the RealmForge software, and initialize its 
state to each generalized state it can enter (as discussed above). The tester 
will then prompt the system to execute each possible scene/menu transition from 
each state, and verify that each transition elapses at most 
\hyperlink{TRANSITION_TIME}{TRANSITION\_\allowbreak TIME} seconds. This 
includes one transition for each time the game can transition to a new overall 
state (i.e. from the main menu to the save data management menu); granular 
transitions are not tested (such as the system transitioning from one state of 
an enemy encounter to another). 

The tester will also verify that the system displays a valid transition screen, 
as described above. 

Since this test involves verifying qualities of many different transitions the 
system can execute, it is suitable for each transition to be verified a minimum 
of \hyperlink{TRANSITION_TESTS}{TRANSITION\_\allowbreak TESTS} times. This 
ensures that the test is feasible in the context of the project.}

\item \par\noindent\refstepcounter{SNFT}\label{UISNFTflashinglights}%
\textbf{\theSNFT} Review of Flashing Lights in Game Content\par\vspace{8pt}
\testfield{Type}{Static, Manual}
\testfield{How test will be performed}{The RealmForge software's source code 
will be reviewed by the RealmForge developers to ensure that any graphical 
displays or changes follow the WCAG 2.2 accessibility guidelines' guideline 
2.3.1 \cite{WCAG}. This guideline mandates that presented content does not 
display any flashing images more than three times in any one second period, to 
reduce any risks to individuals with photosensitive epilepsy.

Each module of 
the RealmForge software's source code will be verified against this guideline, 
during regular reviews held by the RealmForge development team following the 
completion of a new section of source code. Sections of source code that 
display graphical outputs to the user in a timely fashion will be specifically 
reviewed, to ensure that they do not display any excessively bright images that 
change more than three times in one second.}

\item \par\noindent\refstepcounter{SNFT}\label{UISNFTcolours}%
\textbf{\theSNFT} Review of Distinguishable Colours in Game 
Content\par\vspace{8pt}
\testfield{Type}{Static, Manual}
\testfield{How test will be performed}{The RealmForge software's source code 
will be reviewed by the RealmForge developers to ensure that any graphical 
indicators or interface elements/buttons used in the software follow the WCAG 
2.2 accessibility 
guidelines' guideline 
1.4.1 \cite{WCAG}. This guideline mandates that ``color is not used as the 
only 
visual means of conveying information, indicating an action, prompting a 
response, or distinguishing a visual element'' \cite{WCAG}.

Each module of 
the RealmForge software's source code will be verified against this guideline, 
during regular reviews held by the RealmForge development team following the 
completion of a new section of source code. Sections of source code that 
display graphical outputs to the user that must be differentiated from other 
graphics (such as interface elements, system messages, etc.) will be 
specifically 
reviewed, to ensure that they provide a means of distinguishing these elements 
from others without relying on using colour.}

\end{enumerate}
