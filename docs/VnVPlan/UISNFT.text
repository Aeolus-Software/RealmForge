The system tests listed below are planned to verify the implemented system as a 
whole against non-functional requirements related to its user interface 
component. 
These requirements can be found in the SRS \cite{SRS}, listed in 
section S.2's 
non-functional requirements (they are spread across multiple categories), as 
well as in section 
S.2's Safety and Security Requirements (some safety requirements presented in 
the document relate to non-functional qualities of the system). Tracebility 
relationships between all 
system tests and covered requirements are provided in the traceability table in 
section 4.3 of this document.

\begin{enumerate}

\item \nonfunctest{UISNFTmapappearance}
{Game World Location Appearance Variety}
{Dynamic, Manual}
{The RealmForge software has been launched on a compatible device, and 
initialized to a game state where the overall game world is displayed during a 
gameplay session.}
{The game world is traversed using inputs to the software as a player would 
during gameplay (assuming the software is 
initialized to a state where the player is permitted to move to each world 
location), using a valid input device (keyboard and mouse, or a controller). }
