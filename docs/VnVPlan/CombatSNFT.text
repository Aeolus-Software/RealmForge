The system tests listed below are planned to verify the implemented system as a 
whole against non-functional requirements related to the area of combat component 
of the system. These requirements can be found in the SRS [CITATION NEEDED], under section S.2's 
Non-Functional Requirements and Safety and Security Requirments. 

\begin{enumerate}

\item \nonfunctest{CombatSNFTActionSelection}
{Action Selection Feedback}
{Dynamic, Manual}
{The RealmForge software has been launched on a compatible device, and initialized to a game state where the player is in a combat encounter. In this state the player can select an action.}
{The system proceeds to a state where the player can select an action through inputs made using a valid input device (keyboard and mouse, or controller) This can be on first entrance to a combat encounter, or action returning to the player after enemy action(s).}
{The system displays the various action options the player has access to (with proper descriptions), and properly signifies to the player which actions are or are not valid, giving the player proper feedback. The visuals for valid/not valid actions are distinct from each other (following required accessibility guidelines).}
{The system tester will launch the RealmForge software, and initialize its state to a combat encounter. The tester will visually inspect the combat UI to evaluate visual indication of action validity and proper description of actions, and then will select the action using a valid input device as a player would, verifying the validity of the actions (visual indication should match what the system allows). This is repeated as necessary for the various player actions present in the UI.}

\item \nonfunctest{CombatSNFTActionFeedback}
{Combat Action Feedback}
{Dynamic, Manual}
{The RealmForge software has been launched on a compatible device, and initialized to a game state where the player is in a combat encounter. In this state the player can select an action (either offensive or defensive), or is awaiting an enemy action.}
{A combat action (attack, heal, etc.) is selected using inputs to the software using a valid input device (keyboard and mouse, or controller), or the system is transitioned to a state where enemy action is awaited.}
{The system completes the player/enemy action if valid, displays the proper visual for the action taken, and updates any visual indicators or stat changes (e.g. health). These action visuals are distinct from each other (following required accessibility guidelines).}
{The system tester will launch the RealmForge software, and initialize its state to a combat encounter. The tester will then select an action from the combat UI using a valid input device as a player would. They will verify that for each action selected, the correct distinct visual corresponding to the action is displayed, and that any visual indicators of system changes are displaying the proper updated information. This is repeated as necessary for the various player/enemy actions present, both offensive and defensive.}

\item \nonfunctest{CombatSNFTEnemyVariation}
{Enemy Encounter Variation}
{Dynamic, Manual}
{The RealmForge software has been launched on a compatible device, and initialized to a game state where the player is in a combat encounter.}
{A combat action that affects an enemy is selected using a valid input device (keyboard and mouse, or controller).}
{The system completes the player action if valid, displays the proper visual for the action taken, and updates any visual indicators or stat changes (e.g. health). These action visuals are distinct from each other (following required accessibility guidelines).}
{The system tester will launch the RealmForge software, and initialize its state to a combat encounter. The tester will visually inspect the enemy sprites and visible stats to evaluate visual indication of enemy variability. They will then select an action using a valid input device as a player would, and evaluate if enemies have varying statistics that are hinted at through their visuals (e.g. the one with a shield has higher defense and loses less health from an attack). This is repeated as necessary for the relevant enemies present in the encounter, and repeated for as many encounters as necessary to prove enemy variability.}

\end{enumerate}
