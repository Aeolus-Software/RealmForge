The verification and validation plan is an artifact in itself; it too must be verified.\\
Internal reviews for the verification plan are as follows:  
\begin{itemize}
    \item Peer reviews should be collected from classmates, another capstone group(s), and teaching assistants; these are formatted into GitHub issues. The suggestions and critiques should then be responded to from a project member with another GitHub issue that lays out the actions and changes required; these issues are labeled as ``feedback response".  
    % \item Documentation review from Prof. Welch for project feasiblity and scope overview
    \item Each member should create GitHub issues for their written sections. The issues should be updated and maintained to accurate feedback and response.  
    \item Each team member will have an evenly divide number of sections and system tests corresponding to the document to look over such that the VnV plan will be completely reviewed. Each team member should note the section
    they are reviewing via the corresponding issue created.
    \item Mutation testing that introduces small defects to the requirements, test cases, and traceabilty links in order to 
    determine if the VnV plan verfication can detect actual documentation faults
\end{itemize}
\noindent
Below is a checklist to ensure the VnV plan is correct and complete
\begin{itemize}
    \item [$\square$] Does the VnV plan verify all functional requirements
    \item [$\square$] Does the VnV plan verify all nonfunctional requirements
    \item [$\square$] Does the VnV plan verify all safety requirements
    \item [$\square$] Do all the outputs match the system tests desired output
    \item [$\square$] Does the system test cover all requirements listed in the SRS
    \item [$\square$] Do all system tests provide complete traceability
    \item [$\square$] Do all traceability links work 
    \item [$\square$] Are all sections written with correct grammar
    \item [$\square$] Have all team members peer reviewed at least one of each of the other team member's work and the work is satisfactory
    \item [$\square$] Have all peer review (from other teams) issues been resolved
    \item [$\square$] Do all references, acronyms, and internal constants are properly detailed and linked
    \item [$\square$] Does the document cover all points provided in the respective checklists and rubric
    % \item Are all external libraries, third-party components, and 
\end{itemize}
