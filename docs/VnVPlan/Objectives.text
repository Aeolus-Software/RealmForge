The verification and validation plan objective is to build confidence in the functional sustainability of the software product. 
Systems tests are created to ensure the functional, nonfunctional and safety requirements are measured and quantified; 
this provides evidence that fit criteria are met and present in the account of the game. The system tests also reinforce the 
behavior of the game so that the requirements and other elements outlined in the SRS, Design Document and other future documents are tracked. 
\\
\\
\noindent
The VnV plan also makes sure that the game gets as full testing coverage as possible within the boundaries of the project; 
this provides a great steppingstone for \hyperlink{CI}{CI} implementation. Specific tools such as GDUnit4 and GDLint can implement the 
system tests (appropriate ones) to maintain coding standards, and requirement completion.
\\
\\
\noindent
Other testings methods are also used to improve the quality of the software documentation and product. 
Code reviews, requirement reviews and document reviews are done by members within the team and peers from other associations. 
Usability testing will be done so that testing and feedback provided by the major stakeholder that are not in the capstone social group. 
Usability testing will help give direction on the requirements in order to create more or modify existing ones based on the results. 
All in all, this solidifies and strengthens the documentation and requirements which in turn improves the software product.
Overall, the verification and validation plan contributes to the security in making sure the functional of the software is maintained and correctly resolved. The VnV plan gives a certain confidence level for quality and correctness of the final product.
