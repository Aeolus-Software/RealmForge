The main risks the team is worried about are an initial \textbf{Learning Curve} and the possibility of \textbf{Scope Creep}.
\\

\noindent With whatever expected technology the team will use, there will certainly be a learning curve for the game engine/framework chosen. This could prove to be a barrier when attempting to create more complex portions of the project. Although today's technologies such as AI and LLMs and other tools have made learning and writing code physically easier, there is still a limit to how much automated code generation can be trusted. These tools could make code more difficult to refactor and extend later, along with possibly causing massive amounts of bugs and unforeseen errors. 
\\

\noindent With the development tools available, it may become difficult to avoid scope creep since there can always be another feature to add, which then requires more complexity and more time to implement. This is especially relevant as you iterate on and refactor your code more and more, and can lead to not being able to finish components of the game by the deadlines.
\\

\noindent To prove this risk can be overcome, the proof of concept demonstration may include elements such as:
\begin{itemize}
        \item Basic unit testing
        \item Traversal to different areas through simple branched paths
        \item The core compnents of the main encounter/combat loop
        \item Reward options upon encounter completion (different between runs)
\end{itemize}
Important gameplay features will have some element of modifiability and/or scalability to them to prove that they are robust and that added complexity will not hinder the project more than the team can handle.
